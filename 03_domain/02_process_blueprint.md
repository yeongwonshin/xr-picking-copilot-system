# Process Blueprint

## 피킹 프로세스
1. WMS가 출고 주문과 재고 가용성을 확정한다.
2. Integration Layer가 주문을 내부 작업 이벤트로 정규화한다.
3. Task Orchestrator가 존·우선순위·작업자 상태를 고려해 PickWave를 구성한다.
4. XR Worker App이 작업 카드와 경로를 표시한다.
5. 작업자는 로케이션에 도착해 위치 QR 또는 마커를 확인한다.
6. 상품 바코드와 AI 시각 검증으로 SKU를 확인한다.
7. 수량과 토트 ID를 확인한다.
8. WMS에 작업 라인 완료 이벤트를 전송한다.
9. 포장 단계에서 주문별 구성품과 포장 지시를 재검증한다.

## 예외 프로세스
| 예외 | 작업자 UX | 시스템 처리 | 관리자 처리 |
|---|---|---|---|
| 재고 부족 | “재고 부족” 음성 명령 | ExceptionCase 생성 | 대체 위치/보충 지시 |
| 위치 불일치 | 경고 + 재스캔 | 로케이션 오류 이벤트 | 라벨 교체/맵 수정 |
| 유사 SKU 혼동 | 이미지 비교 + 경고 | AI confidence 낮음 | 재교육 데이터 축적 |
| 네트워크 장애 | 오프라인 큐 표시 | 로컬 캐시 저장 | 복구 후 동기화 확인 |
| 장비 배터리 낮음 | 배터리 경고 | 디바이스 교체 요청 | 충전 스테이션 운영 |

## 현장 설계 팁
- SKU 이미지 마스터 품질이 낮으면 AI 성능보다 UX가 먼저 무너진다.
- 유사 SKU는 같은 작업자·같은 토트에 몰아넣지 않는 정책이 효과적이다.
- 물류센터별 Wi-Fi 음영지역 사전 측정이 필수다.
